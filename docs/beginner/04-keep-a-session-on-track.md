# Как удержать сессию в рабочем русле <a id="keep-a-session-on-track"></a>

<sub>**Начальный уровень** · Урок 4 из 5 · около 20 минут · Нужно: [Первое изменение: от запроса до коммита](03-first-change.md) · Проверено на Claude Code v2.1.285 (stable) 2026-10-05</sub>

<a id="goal"></a>
## Цель

После урока вы умеете удерживать сессию в рабочем русле: смотреть, насколько заполнен контекст, очищать или сжимать его, откатывать изменение и возвращаться к прежнему разговору.

<a id="you-need"></a>
## Что понадобится

- Ваша копия шаблона для практики без незакоммиченных изменений и Node.js LTS (в Codespace на вашей копии он есть). Если хотите практиковаться в своём репозитории, копию шаблона всё равно оставьте: проверка запускается из неё. Если ещё не сделали, создайте в репозитории папку `.practice/`, как описано в [уроке 1](01-install-and-look-around.md#you-need). Начинайте и в этом репозитории без незакоммиченных изменений: закоммитьте их или отложите командой `git stash push --include-untracked`.
- Расход: небольшой.

<a id="the-idea"></a>
## Идея

Всё, что есть в разговоре, — ваши запросы, ответы Claude и каждый прочитанный им файл — лежит в окне контекста сессии. Окно большое, но не бесконечное, а длинный блуждающий разговор оставляет Claude меньше места для работы, которая важна сейчас ([Как устроено окно контекста](https://code.claude.com/docs/en/context-window)). Пять команд помогают держать его под контролем ([Команды](https://code.claude.com/docs/en/commands)):

| Команда | Что делает |
|---|---|
| `/context` | Показывает цветной сеткой, насколько заполнено окно контекста |
| `/compact` | Сжимает разговор до краткого пересказа, чтобы освободить место |
| `/clear` | Начинает новый разговор с пустым контекстом |
| `/rewind` | Возвращается к прежнему запросу, восстанавливая код, разговор или и то и другое |
| `/resume` | Продолжает прежний разговор |

Сжимайте контекст, когда хотите продолжить ту же задачу; очищайте, когда начинаете другую. Откатывайте (rewind), когда изменение пошло не туда ([Контрольные точки](https://code.claude.com/docs/en/checkpointing)).

<a id="worked-example"></a>
## Разбор на примере

1. Запустите `claude` в своей учебной копии и введите `/context`. Сетка показывает, какая часть окна занята, с разбивкой по категориям, включая ваши сообщения и загруженные файлы памяти, такие как `CLAUDE.md` ([Как устроено окно контекста](https://code.claude.com/docs/en/context-window)). В вашей учебной копии `CLAUDE.md` пока нет, поэтому файлов памяти может не быть; его добавит [урок 5](05-project-memory.md).
2. Заполните окно немного:

   ```text
   Объясни, как src/check-links.js решает, что ссылка битая.
   ```

   Снова выполните `/context`: часть с сообщениями выросла.
3. Сожмите контекст, сказав Claude, что сохранить:

   ```text
   /compact сохрани то, что мы узнали про check-links.js
   ```

   Разговор заменяется кратким пересказом: в `/context` часть с сообщениями уменьшается, а свободное место растёт. После одного короткого вопроса пересказывать почти нечего, поэтому разница невелика; сжатие окупается, когда разговор становится длинным.
4. Сделайте изменение, которое можно откатить. Rewind не отменяет изменения, которые Claude вносит запуском команд (см. [Осторожно](#watch-out)), поэтому в запросе указан его инструмент редактирования файлов. Одобрите правку, если Claude спросит:

   ```text
   В src/cli.js замени сообщение об успехе на "All relative links are fine." Используй свой инструмент редактирования файлов, а не команду оболочки.
   ```

   Во втором терминале в той же папке сохраните то, что видит git:

   ```bash
   git status --porcelain > .practice/b-4-before-rewind.txt
   ```

   В файле будет перечислен `src/cli.js`.
5. Откатите. Введите `/rewind` или дважды нажмите `Esc` при пустой строке ввода. Выберите запрос из шага 4 и пункт **Restore code and conversation** (восстановить код и разговор). Если меню предлагает только **Restore conversation**, варианты с пересказом и **Never mind**, значит, Claude изменил файл командой, а rewind её не отменяет: выберите **Never mind**, закройте меню клавишей `Esc` ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode)), выполните во втором терминале `git restore src/cli.js` и повторите шаг 4.

   Когда код восстановлен, сохраните то, что видит git, во втором терминале:

   ```bash
   git status --porcelain > .practice/b-4-after-rewind.txt
   ```

   Этот файл пуст: правки больше нет. Если рядом с разговором открыта панель диффа, она может всё ещё показывать правку: Claude Code обновляет панель каждый раз, когда Claude правит файл или запускает команду оболочки ([Интерактивный режим](https://code.claude.com/docs/en/interactive-mode#diff-panel)). Пустой файл показывает то, что видит git.
6. Rewind вернул запрос из шага 4 в строку ввода, поэтому всё, что вы введёте сейчас, добавится к нему. Быстро дважды нажмите `Esc`, чтобы очистить строку. Затем введите `/clear`. Разговор начнётся заново с пустым контекстом, а старый останется доступным.
7. Введите `/exit`, затем заново откройте последний разговор в этой папке ([Управление сессиями](https://code.claude.com/docs/en/sessions)):

   ```bash
   claude --continue
   ```

   Если откроется пустой разговор из шага 6, выполните `/resume` и выберите прежний. Внутри сессии `/resume` без аргумента открывает список прежних разговоров. Выбранный разговор может всё ещё показывать откатанную правку, потому что он был сохранён до отката. Ваши файлы остаются такими, какими их оставил rewind (`git status --porcelain` ничего не печатает), поэтому не просите Claude внести правку заново. Если Claude предложит повторить откатанную правку, откажитесь.

<a id="your-turn"></a>
## Ваша очередь

Повторите пример в учебной копии или в своём репозитории:

1. Выполните `/context`, задайте один вопрос о коде и снова выполните `/context`.
2. Выполните `/compact` с фразой о том, что сохранить.
3. Попросите небольшую правку одного файла, закончив запрос словами «Используй свой инструмент редактирования файлов, а не команду оболочки.», и одобрите её, если Claude спросит. Сохраните `git status --porcelain > .practice/b-4-before-rewind.txt`.
4. Откатите этот запрос пунктом **Restore code and conversation** и сохраните `git status --porcelain > .practice/b-4-after-rewind.txt`.
5. Быстро дважды нажмите `Esc`, чтобы очистить восстановленный запрос, затем выполните `/clear`, потом `/exit`, потом `claude --continue`.

<a id="check"></a>
## Проверка

Урок пройден, когда выполнено всё:

- [ ] `.practice/b-4-before-rewind.txt` перечисляет файл, который изменил Claude: `cat .practice/b-4-before-rewind.txt`.
- [ ] `.practice/b-4-after-rewind.txt` не перечисляет файлов: `cat .practice/b-4-after-rewind.txt` ничего не печатает.
- [ ] Самопроверка (не проверяется автоматически): вы можете сказать, когда использовали бы `/compact`, а когда `/clear`.

Запустите `npm run check -- b-4` в учебной копии. В своём репозитории вместо этого запустите из учебной копии `npm run check -- b-4 --dir <your repo>`.

Если первый файл пуст, вы сохранили его до правки; внесите правку снова, сохраните файл после неё и откатите ещё раз. Если второй файл всё ещё перечисляет файл, изменённый Claude, откатите этот запрос вариантом, который восстанавливает код, и сохраните второй файл снова. Когда меню уже не показывает этот запрос (после **Restore conversation**) или не предлагает варианта, восстанавливающего код (Claude использовал команду), выполните `git restore <file>` и повторите шаги 3 и 4 из раздела «Ваша очередь». Файлы, которые вы изменили до урока, тоже останутся в списке, потому что rewind их не отменяет: закоммитьте их или отложите командой `git stash push --include-untracked`, затем снова сохраните второй файл.

<a id="watch-out"></a>
## Осторожно

- Rewind отменяет только правки, которые Claude внёс своими инструментами редактирования файлов. Изменения от запущенных им команд, например удаление файла через `rm`, остаются ([Контрольные точки](https://code.claude.com/docs/en/checkpointing#bash-command-changes-not-tracked)); коммитьте работу, чтобы git мог её вернуть.
